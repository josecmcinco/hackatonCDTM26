# Revisión de código

1. Lee el objetivo de la tarea, los acuerdos relevantes y el diff completo.
2. Prioriza defectos concretos: errores funcionales, regresiones, fallos de seguridad, manejo incorrecto de datos y validaciones ausentes.
3. Comprueba los flujos principales y las pruebas pertinentes; no asumas que una compilación equivale a comportamiento correcto.
4. Comunica primero los hallazgos, ordenados por gravedad, con archivo, ubicación, impacto y una forma de reproducirlos cuando sea posible.
5. Distingue defectos de preferencias o mejoras opcionales. No modifiques código durante una revisión salvo que se solicite.
6. Si no hay hallazgos, indícalo junto con las comprobaciones realizadas y sus límites.

## Resultado

Una revisión accionable que permita al equipo corregir riesgos importantes sin distraerse con cambios cosméticos.
